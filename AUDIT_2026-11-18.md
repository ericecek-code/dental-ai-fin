## 1. P0 — kritické

### 1.1 Gemini API kľúč natvrdo v tracked zdrojáku (verejné repo)
- **Kde:** `backend/app/ml/gemini_vision.py:15` (`GEMINI_API_KEY = "AIza..."` — redigované).
- **Prečo:** súbor je v gite (`git ls-files`), repo je podľa `STATUS_PROJEKTU.md` public. Kľúč je kompromitovaný bez ohľadu na to, či ho niekto zneužil.
- **Dopad:** zneužitie kvóty / fakturácie, možné znefunkčnenie Gemini funkcií.
- **Oprava:** kľúč **revokovať v Google AI Studio**, načítať z `settings.gemini_api_key` (env `GEMINI_API_KEY`), do repa dať len prázdny príklad. Doplniť `gitleaks`/`detect-secrets` do pre-commit a CI.

### 1.2 GitHub PAT v plaintexte v git remote URL
- **Kde:** `git remote -v` → `ericecek https://ghp_...@github.com/ericecek-code/dental-ai-fin.git` (uložené v `.git/config`).
- **Prečo:** token je čitateľný v každej zálohe/zip-e priečinka, v histórii shellu a v akomkoľvek logu, ktorý vypíše remote.
- **Oprava:** token revokovať na GitHube, nastaviť remote bez tokenu (`git remote set-url`) a použiť credential manager / SSH. Prekontrolovať, či token nefiguruje v `.github` workflow alebo skriptoch.

### 1.3 `.env` nie je v `.gitignore`, hoci dokumentácia tvrdí opak
- **Kde:** `.gitignore` — chýba akýkoľvek `.env` pattern; `.env.example:2` tvrdí „.gitignore ho blokuje“; reálne existuje `backend/.env` (untracked).
- **Dopad:** jediné `git add -A` commitne konfiguráciu s `API_TOKEN` a CORS do verejného repa.
- **Oprava:** pridať `.env`, `.env.*`, `!.env.example` do `.gitignore`, overiť `git check-ignore backend/.env`.

### 1.4 `requirements.txt` neobsahuje reálne runtime závislosti
- **Kde:** `backend/requirements.txt` vs `backend/app/core/config.py:8` (`pydantic_settings`) a `backend/app/ml/gemini_vision.py:9` (`requests`).
- **Dopad:** čistá inštalácia (Docker, Render, CI) spadne na `ModuleNotFoundError: pydantic_settings` ešte pred štartom aplikácie. Lokálne to „funguje“ len preto, že vývojové prostredie má balíky navyše.
- **Oprava:** doplniť `pydantic-settings`, `requests` (a `sqlalchemy` iba ak sa mŕtvy modul naozaj používa — viď 2.10). Overiť `pip install -r` v čistom venv.

### 1.5 Nekonzistentná logika prístupového tokenu — zlyháva „open“ aj „closed“
- **Kde:**
  - `backend/app/middleware/auth.py:51` — vypína auth pri `replace-with-secure-token-in-production`
  - `backend/app/api/routes/analyze.py:151` — ten istý placeholder
  - `backend/app/api/routes/results.py:33,48` — **iný** placeholder `replace-with-generated-token`
  - `.env.example:23` odporúča práve `replace-with-generated-token`
  - `backend/app/ml/database.py:69–81` — `access_token` sa **neukladá** do DB
  - `backend/app/api/routes/history.py` — žiadna kontrola `access_token`
- **Dôsledky (overené čítaním kódu):**
  1. S predvoleným `backend/.env` (`replace-with-secure-token-in-production`) middleware aj `/analyze` auth vypnú, ale `/results/...` ju zapnú → obrázky a PDF bez `?token=` vrátia 403, hoci analýza prešla.
  2. Pri výsledkoch z DB chýba `access_token`, takže `if expected and ...` preskočí kontrolu → ochrana **fail-open**.
  3. `history` endpointy vracajú dáta bez per-job tokenu.
  4. Token v query stringu sa loguje do access logov (Render/nginx) — zlý zvyk pri PHI.
- **Oprava:** jeden `require_token` dependency, hlavička `X-API-Key`, žiadne query tokeny, žiadne „magic placeholder“ reťazce (použiť `None` = vypnuté, `SecretStr`), token hash ukladať do DB alebo per-job token úplne zrušiť a použiť session/JWT.

### 1.6 CI je červené — 4 padajúce testy
- **Dôkaz:** `pytest` → `test_config.py::test_default_version`, `test_config.py::test_default_confidence` (očakáva 0.05, kód má 0.25), `test_detector.py::test_label_matches_key`, `test_detector.py::test_known_class_returns_info` (testy čakajú anglické labely, kód vracia slovenské).
- **Dopad:** `.github/workflows/ci.yml` beží na každý push do `main` → pipeline je trvale red, badge v README klame.
- **Oprava:** zosúladiť testy s aktuálnym kontraktom (alebo naopak), pridať chýbajúce závislosti do CI a testy pre auth/vision (dnes ich niet — preto unikol bug 2.9).

### 1.7 Health endpointy ukazujú na neexistujúcu cestu k modelu
- **Kde:** `backend/app/api/routes/health.py:14–15` → `backend/app/weights` (neexistuje); `backend/app/main.py:152–155` → `<repo>/weights` (neexistuje).
- **Reálne:** `backend/weights/yolov8x_dental.pt` (overené).
- **Dopad:** `/health` aj `/health/v1` trvale hlásia `model_loaded: false` → monitoring a Render healthcheck sú nepoužiteľné.
- **Oprava:** jedna funkcia `resolve_model_path()` v `config.py` (env `MODEL_PATH` s defaultom `backend/weights/...`), použitá v detektore aj v health.

### 1.8 `Dockerfile.render` — healthcheck na inom porte, než na akom beží server
- **Kde:** `Dockerfile.render:44–45` testuje `localhost:8000`, ale `CMD` (riadok 49) používa `$PORT` (Render typicky 10000).
- **Dopad:** lokálne/na platforme, ktorá `HEALTHCHECK` rešpektuje, je kontajner trvale „unhealthy“; na Renderi je navyše build extrémne veľký (viď 2.16).
- **Oprava:** healthcheck cez `$PORT`, `python -c "import os,urllib.request; urllib.request.urlopen(f'http://127.0.0.1:{os.environ.get(\"PORT\",8000)}/health')"`, alebo healthcheck vypnúť a nastaviť ho v Render UI.
